# StructMark 優化 Token 測試

執行：`npm run benchmark:optimization`  
Tokenizer：`tiktoken 0.14.0` 的 `cl100k_base`、`o200k_base`。完整結果見 [`benchmark/optimization-results.json`](../benchmark/optimization-results.json)。

## 簡化指令

比較 `&warning[title=警告] ... &end` 與語義相同的 `&w[警告] ... &e`，包含 1、3、10、50、100 行內容：

| Tokenizer | 完整指令 | 簡化指令 | 減少 | 比例 |
| --- | ---: | ---: | ---: | ---: |
| `cl100k_base` | 4155 | 4135 | 20 | 0.48% |
| `o200k_base` | 2674 | 2654 | 20 | 0.75% |

簡化指令確實有效，但單獨縮短指令名稱的收益有限；內容越長，主要節省來自只保留一次區塊標記。

## 結構化資料與上下文

| 類別 | `cl100k_base` | `o200k_base` |
| --- | ---: | ---: |
| 長提示區塊 | 3.59% | 5.65% |
| 原生表格 | 12.69% | 12.69% |
| Schema rows | 39.17% | 39.17% |
| 完整文件 → 目標章節 | 90.00% | 90.00% |

這些數字是特定合成語料的實測，不代表所有文件都能得到相同比例。尤其上下文測試比較的是完整十節文件與單一目標節，屬於檢索／擷取收益，不是單純語法收益。

## 結論

`.sm` 的簡化語法有可測量但有限的收益；較大的收益來自減少重複結構、Schema 驅動資料，以及只傳遞必要章節。這也是後續優化應優先處理的方向。
