# StructMark 語法設計決策（V1.0）

狀態：語法草案，可修改；不承諾未來維持二進位或來源相容性。

## 1. 最少的原生標記種類

| 用途 | 決議 | 理由 |
|---|---|---|
| 行內格式 | `*[文字]`、`/[文字]` 等 | 一個右中括號結束，不重複尾端標記 |
| 內容與參數 | `[]` | 明確表示內容或附屬參數 |
| 連結與資源目標 | `(目標)` | 類 Markdown，與內容界線分離 |
| 標題 ID | `#2 標題 (#id)` | ID 只在標題行尾成立，不與正文中括號衝突 |
| 區塊指令 | `&note[title="補充"]` 起始、獨立行 `&end` 結束 | 避免多種區塊圍欄混用 |
| 行內指令 | `&kbd[Ctrl+C]`、`&ref[id]` | 以 `&` 作為固定語義前綴 |
| 原生屬性 | `[key=value #id]` | 避免原生標記引入 `{}` |
| 嵌入格式 | 保留 JSON、LaTeX、程式碼內的 `{}` | 不改寫第三方格式文法 |
| 圖片 | `![alt](resource)` | `!` 是區分「圖片嵌入」與「圖片檔案超連結」的必要判別符 |
| 有序清單 | `1. 項目` 或 `. 項目` | 前者指定起始編號，後者自動編號 |
| 任務完成 | `- [o]` | 依使用者設計，與 GFM 的 `[x]` 不同 |
| 副檔名 | `.sm` | 短、可辨識，並與 StructMark 語言名稱一致 |

## 2. 刪除的多餘做法

- 不再使用 `:::note ... :::`，改為 `&note ... &end`。
- 不再使用 `:kbd[Ctrl+C]`，改為 `&kbd[Ctrl+C]`。
- Setext 標題 `文字\n---` 不納入正式文法。
- 在原生語法中，不再推薦 `{width=600}`，採用 `[width=600]`；大括號仍能出現在 JSON 與 LaTeX 中。
- 不根據 `.jpg`、`.png` 或 MIME 類型猜測 `[文字](URL)` 是圖片。
- 同一段學術引用只使用 `[&key]` 基本語法。敘述式引用與頁碼等特性尚未完成正式輸出。

## 3. 如何區分同樣的中括號

- `*[內容]`：格式標記之後的第一個中括號是內容。
- `&kbd[內容][title="..."]`：第一組是內容，第二組若為合法屬性則是屬性。
- `&note[title="..."]`：區塊起始行的第一組是屬性。
- `[文字](URL)`：只有中括號後面緊接完整合法小括號目標，才是連結。
- `![文字](URL)`：加 `!` 才代表嵌入圖片。
- `[&key]` / `[^id]`：依固定前綴解為文獻引用 / 註腳引用。
- `[[文件|顯示]]`：Wiki 連結候選，目標解析留待跨檔系統。
- `[普通文字]`：無其他前綴、非連結時保留為字面文字。
- `[#id]` 單獨出現在一般段落，不代表節點 ID；只有合法後綴位置才能成為屬性。

## 4. 規格與實作需分開判斷

採用某種符號，不代表已完成所有語義：`&equation` 不等於已完成 LaTeX 排版；`[&key]` 不等於已完成 APA；`&table[format=json]` 也不等於具有複雜表格的全部驗證規則。各項程度詳見 `STATUS_AND_ROADMAP.md`。
