# StructMark 1.5：穩定工具與更易讀的 AST

StructMark 1.5 延續 1.1 穩定語法。它主要改善文件分析流程與網站操作，不改變 `.sm` 副檔名、主要標記或既有 AST 節點契約。

## 工作區索引

`buildWorkspaceIndex(documents)` 是不依賴 Node.js 檔案系統的 TypeScript API。輸入清單為 `{path, document}`，其中 `path` 必須是工作區內 `.sm` 相對路徑。結果包含 `documents`、`identifiers`、`references`、`diagnostics`，診斷上的 `file` 指向造成問題的來源檔案。既有 `validateWorkspace` 仍提供原本的 `Diagnostic[]` 介面。

此索引只收集已提供的 AST，不會掃描硬碟、不會索引圖像與其他外部資源，也不會自動連網。工作區路徑中的 `..` 只能在根目錄內移動。

## CLI 的來源安全

`format --write` 是唯一會替換原始檔的 CLI 選項。它在原檔所在資料夾建立暫存檔，同步寫入後替換原始檔；拒絕符號連結，並沿用原始檔案權限模式。若在替換前出錯，會嘗試刪除暫存檔。

`convert --strict` 如果偵測到解析錯誤、警告或已知語義遺失，會回傳非零退出碼，**不建立**目標輸出。這個保護不表示 Markdown 轉換已達完整 CommonMark 等價。

## AST Tree

網站 Playground 多了一個 AST Tree 頁籤。它使用 `.sm` Parser 已建立的節點，呈現巢狀標題、段落、清單、表格與行內節點；可用滑鼠或鍵盤展開，點選節點可反白原始碼對應範圍。大型文件最多先顯示固定數量的節點，避免一次建立太多 DOM 元素。原本的 HTML 與 JSON 檢視保持不變。

## 官方文件的來源

網站教學與語法範例以 `apps/site/content/zh-tw/*.sm`、`apps/site/content/en/*.sm` 為唯一來源；`npm run docs:check` 檢查檔名對應及解析診斷。`npm run docs:export` 可以依此產生 Markdown 參考副本，但某些 StructMark 指令無法被 Markdown 完整表達，產生時會顯示警告。

`docs/SPECIFICATION.md` 是獨立的**正式語法規範**，不由前述網站內容自動產生。請勿將網站教學與規範全文視為完全相同的文件。

## 本版沒有實作的功能

- 完整 CSL 樣式引擎、完整 CommonMark/GFM、完整 LaTeX 巨集。
- 增量解析器、Language Server、完整桌面 IDE。
- 能從 AST 無損重建所有原始空白、註解與指令的 Writer。
- 正式線上部署（提供可建置原始碼；是否成功部署須以實際 CI 為準）。

完整測試與相依套件限制另見根目錄 `VALIDATION.md`。
