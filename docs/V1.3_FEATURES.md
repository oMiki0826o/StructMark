# StructMark 1.2 → 1.3 功能與界線

這次在原有 v1.1.1 基礎上增加工具與文件體驗，不修改既有 `.sm` 的正式語法。版本 `1.3.0` 是 npm 套件版本；現有 AST 的 `version: "1.1"` 仍是相容語法版本。

## v1.2 開發工具

- 以 `visitAst(document, {enter, leave})` 訪問 Document、Block、Inline、清單項目與表格。`enter` 回傳 `false` 可略過子節點，但 `leave` 仍被呼叫；Visitor 不修改 AST。
- 新增 Node CLI：檢查、HTML、AST、Markdown 轉換、安全格式化、工作區驗證；參見 [CLI](./CLI.md)。
- Playground 增加七種中英文可切換語法範例、AST JSON、可點擊診斷定位，保留本機草稿。
- 文件程式碼支援一鍵在 Playground 試用，但只對明確標示 `.sm` 的範例提供此入口。

## v1.3 文件與工作區

- `resolveWorkspaceReference()` 按來源 `.sm` 所在目錄解析同資料夾檔名、`./` 與 `../`，ID 採 NFC，拒絕越界與非 `.sm` 的檔案目標。
- 文件搜尋由建置時讀取既有雙語 `.sm` 生成索引，在瀏覽器本機搜尋；不需要搜尋後端。
- 增加 round-trip、工作區、CLI 與大型文件驗證案例。維持既有 Fuzz 與效能測試工具。

## 不屬於相容承諾的功能

這一版**沒有**提供完整 CommonMark/GFM、完整 BibTeX/CSL 樣式引擎、完整 LaTeX 巨集相容、語言伺服器、增量 Parser 或 AST 無損重新排版。`formatSource` 是保守的換行正規化工具；Markdown 匯入只處理已文件化的子集。瀏覽器編輯器有輸入長度上限，不適合作為超大型文件 IDE。

## 品質驗收

- `npm test`：單元與整合測試。
- `npm run fuzz`：固定亂數異常輸入測試。
- `npm run benchmark:perf`：12,000 區塊基準。
- `cd apps/site && npm test && npm run build`：雙語站點測試及 Next.js 靜態匯出。

以上指令的實際執行紀錄、缺少依賴等限制，在交付包根目錄 `VALIDATION.md` 中獨立說明。
